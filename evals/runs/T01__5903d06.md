# Salon Data Export — SPEC

> Authored via `dev-pipeline:spec-elicitor` on 2026-07-06.

## 1. Problem Statement (问题陈述)

Salon owners have no way to get their business data (customers, bookings) out of
the platform. Today every request goes to support, who run manual database
queries per salon — slow, unscalable, and error-prone. Owners need the data for
their accountants (quarterly), and the gap has been raised by two paying salons

## 2. Proposed Solution (方案描述)

A self-serve "Export data" section on the admin Settings page. The owner picks a
dataset — **Customers** or **Bookings** — and clicks Export; the browser
downloads a CSV for their salon only. The bookings export accepts an optional
from/to date-range filter (accountants export per quarter); the customers export
takes no filter. Download is synchronous — no background job, no email step.

## 3. Technical Constraints (技术约束)

- **Apps touched**: api (new export endpoint/service), web (Settings page export UI)
- **Stack constraints**: stay within current stack (NestJS, Prisma, Next.js); a
  small CSV-serialization dependency is acceptable if verified
- **Performance**: largest tenant ≈ 8k customers / 40k bookings — synchronous
  streaming is sufficient; see Quality Criteria for the budget
- **Multi-tenancy**: every query tenant-scoped; endpoint derives tenant from the
  authenticated admin context, never from client input
- **Locales**: en + zh — all UI strings via translation keys in both message files
- **Compliance / security**: exports contain customer PII → admin-role auth
  required; every export audit-logged
- **Integration boundaries**: none — no external APIs

## 4. Non-goals (明确不做的事)

- Other formats (Excel / JSON / PDF) — CSV only this round; accountant tooling reads CSV
- Scheduled or emailed exports — on-demand only; revisit if usage shows a cadence
- Customer-facing GDPR self-export — different population, different auth surface; own SPEC later
- Column customization or filters beyond the bookings date range — fixed columns keep the contract testable

## 5. Success Criteria (成功标准)

- [ ] Admin clicks Export on Settings → a valid CSV downloads, opens cleanly in
      Excel/Numbers, and row counts match the database for that salon
- [ ] Bookings export respects the optional from/to date-range filter
- [ ] A salon can never receive another salon's rows (tenant isolation proven by test)
- [ ] Non-admin roles receive 403 from the export endpoint (proven by test)

## 6. Quality Criteria (质量标准)

- [ ] Every export is audit-logged with { userId, tenantId, dataset, rowCount, timestamp }
- [ ] Export endpoint rate-limited to 5 requests/min per tenant
- [ ] Perf budget: a 40k-row bookings export completes in < 10s (asserted in test
      against seeded data)
- [ ] Simplicity trade-off (explicit): synchronous streamed response, no job

**Architecture (decisive single choice):**

- **Pattern precedent:** mirror `reporting` module (admin-guarded tenant-scoped GET reads) — `apps/api/src/modules/reporting/reporting.controller.ts:18` for guard stack, `reporting.service.ts:41` for tenant-scoped Prisma read shape.

Calls `audit.log()` with `{ userId, tenantId, dataset, rowCount }` after the stream completes.
  - `ExportController` — `GET /v1/export/customers.csv`, `GET /v1/export/bookings.csv`; `JwtAuthGuard + RolesGuard @Roles('ADMIN')`; tenant via `@TenantId()` (never client input); `@Throttle(5, 60)` per-route override (SPEC quality: 5/min); sets `Content-Type: text/csv; charset=utf-8` + `Content-Disposition: attachment; filename="{slug}-{dataset}-{date}.csv"`.
- **Frontend:**
  - `downloadExport(dataset, range?)` in `apps/web/src/lib/api/export.ts` — follows the invoice-PDF blob-download precedent (`res.blob()` → object URL → anchor click).

- **Data model changes:** none (read-only feature + existing audit table).
