Key hunk in the new loader:

// src/config/config.loader.ts (introduced by e4f9a21)
const raw = fs.readFileSync(join(process.cwd(), 'config', 'env.yaml'), 'utf8');

The loader is invoked lazily by a request-scoped `ConfigResolver` — first touch happens inside the request pipeline, so the app boots, then every request throws.

**Error message / stack trace?**

```
[Bash] gh run list --workflow deploy.yml --limit 3
  → ✓ deploy.yml · main · e4f9a21 · completed 1h58m ago   ← deploy itself was GREEN

[Bash] ssh deploy@prod 'docker logs acme-api --tail 30'
  → ERROR [ExceptionsHandler] ENOENT: no such file or directory,
    open '/app/config/env.yaml'
      at ConfigLoader.load (/app/dist/config/config.loader.js:14)
    (repeats on every request, including /health)
```

**Hypothesis (30 seconds in):** `e4f9a21` reads `config/env.yaml` from `process.cwd()` at request time. The Dockerfile's runtime stage copies only `dist/`, `node_modules/`, `package.json` — **`config/` never enters the image**. Local dev works (file exists in cwd); unit tests green (loader mocked); `deploy.yml`'s Docker build succeeded because the build doesn't execute requests. Classic validate-STEP-5.5 class: *passed local gates, broke the isolated Docker runtime context that only runs on main.*

```
[Bash] grep -n 'COPY' Dockerfile
  → COPY --from=builder /app/dist ./dist
    COPY --from=builder /app/node_modules ./node_modules
    COPY package.json ./
    # no COPY of config/ — hypothesis confirmed at the Dockerfile layer
```
